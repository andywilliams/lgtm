# lgtm — architecture charter

## Purpose & scope boundary
lgtm is a single-operator, human-in-the-loop AI PR-review CLI: it fetches a GitHub PR (or diffs the local working tree), has an LLM CLI produce findings, and keeps the human in charge of what actually gets posted *(inferred from: package.json description "AI-powered PR review CLI — you stay in control"; README)*. A second, unattended posture exists for agents and CI: `--agent`/`--auto` emit findings as JSON, `--batch` posts all comments without prompting, and a GitHub Actions recipe runs it on every PR push *(inferred from: PR titles #9, #11, #24; README "GitHub Actions Mode")*.

**Not for:**
- A hosted service or GitHub App. Only a CLI binary ships (`bin: {"lgtm": "dist/cli.js"}`); the App exists solely as design docs *(inferred from: package.json `bin`; docs/ARCHITECTURE-GITHUB-APP.md and docs/IMPLEMENTATION-TICKETS.md with no server code under src/)*.
- Knowledge-base content. Engineering handbooks live in an external "second brain"; this repo only *fetches* that context through pluggable providers and must keep working without one *(inferred from: src/brain.ts header comment)*.
- DWLF production code. lgtm is standalone local tooling consumed *by* the DWLF workflow, not part of its deploy cascade or code-freeze *(inferred from: engineering handbook "Conventions & deploy")*.

## Interfaces & dependencies
**Exposes**
- The `lgtm` global CLI (`dist/cli.js`), commands: `review [pr]` (incl. `--local` working-tree mode), `arch` (`review [pr]`/`new`/`init` — architecture altitude: decision records against an ARCHITECTURE.md charter, one summary comment, never inline), `standards` (`init` — AI-free, scan-informed generation of STANDARDS.md from the built-in clean-code catalog), `recheck`, `retry`, `tag`, `report`, `quiz` *(inferred from: package.json `bin`; command registrations in src/cli.ts; PR #26)*. Consumers: the operator interactively; coding agents and CI via `--agent`/`--auto` (JSON findings) and `--batch` (post-all, no prompts) *(inferred from: PR titles #8, #11; the DWLF workflow's `lgtm review <PR#> --agent` in CLAUDE.md)*.
- Charter/system input contract: `ARCHITECTURE.md` (root, then `docs/`, then `.lgtm/`) with `title:`/`system:` frontmatter as the only code-parsed fields; `SYSTEM.md` via the `system:` pointer or `LGTM_SYSTEM_DIR` *(inferred from: src/charter.ts; PR #26)*.
- Standards input contract: `STANDARDS.md` (root, then `docs/`, then `.lgtm/`) — the repo's normative selection from the clean-code catalog (`src/standardsCatalog.ts`; rationale in `docs/clean-code-catalog.md`). Consumed by `review` for up to three `(standard <id>)` SUGGESTION findings; only the filename search order is code-parsed; `--no-standards` opts out per run *(src/standards.ts)*.
- Standards OUTPUT contract: `.lgtm/standards.eslint.js` — the mechanical subset of the same selections, emitted by `standards init` as a `standardsRules` fragment (CommonJS or ESM per the target's `package.json type`) for the repo to spread into its own ESLint config. Generated, never hand-edited; regenerating is the supported way to change it. After writing it, `standards init` runs the TARGET repo's own ESLint over the fragment's directory and reports whether their lint now fails, with the cause and the one-line remedy — printed, never applied. `LGTM_LINT_PROBE_TIMEOUT_MS` overrides the 60s bound on that probe; it exists so the timeout branch is reachable in a test in milliseconds rather than a minute, and it is the one env input here that is a testability hook rather than an operator control *(src/standardsLint.ts, src/standardsInterview.ts; DWLF-221, DWLF-223)*.
- `standards review <file|dir>` — the retroactive altitude: renders an existing file as a synthetic whole-file diff, runs ESLint first, and gates the AI pass on outstanding **structural** findings (length/complexity/nesting/params), passing non-structural ones through the `--decided` channel so no capped finding slot is spent on what lint already reported *(src/standardsReview.ts)*.
- `quality` (`baseline`/`hotspots`) — the 4th altitude, Phase 1 (24-Aug-2026): *do the tests actually hold the code down?* Deterministic, no AI call. `baseline` reads a Stryker `mutation.json` (searched at `reports/mutation/mutation.json` → `.lgtm/mutation.json` → `mutation.json`, or `--report`) and writes per-file scores to the target repo's **committed** `.lgtm/mutation-baseline.json`; `hotspots` ranks the burn-down worklist by `(1−score) × mutants × (1+churn)` — a v1 formula, validated by reproducing the dwlf-indicators baseline's known worst files (orderBlocks 3.7%, regime 22.9% flagged on its open bug); full-history churn is a deliberate risk input and a known bias to revisit if a real repo's list orders by age rather than weakness — and cross-checks open issues per file via `gh` (**fix-before-harden**: hardening a file with an open correctness bug cements the bug), degrading to an explicit "unchecked"/"partial" when `gh` fails or truncates. The ranking is deterministic from report+git; the issue column deliberately reads LIVE tracker state *(src/quality.ts)*.
- Local data: a review log in SQLite at `~/.lgtm/reviews.db` (`LGTM_DB_PATH` overrides; src/db.ts) and metrics/false-negative data in cwd-relative `data/reviews.json` (src/metrics/reviewLogger.js). Each logged review carries token figures in three units, never mixed: `token_count` (the historical diff+context length estimate), `sent_tokens` (what lgtm's prompt actually contained, chars/4 — the only figure that tracks a session's growth, since the envelope's totals sum the CLI's internal turns), and the measured columns `prompt_tokens` / `cache_read_tokens` / `cache_creation_tokens` / `output_tokens` / `cost_usd` / `duration_ms` / `model_id`, present only when `usage_source` is `'measured'` (every model call in the run returned an envelope) or `'partial'` (the review's calls did, the verifier pass's did not — a codex verifier reports nothing; its own `verify_*` columns are then NULL). Agent-mode output exposes the same as `context.usage`. Every review — PR **and** `--local` — is also a **round** under a `round_key` (`pr:<n>` or `local:<branch>`), with one `findings` row per finding (severity, `kind` — `added` / `removed` (a deleted guard, test or call) / `missing` (a write with no reader updated, a branch with no test) — `confidence`, file, line, and an identity of file + the reviewer's own fingerprint, the symbol at fault, falling back to the normalised title for rows written before that; a round offers BOTH spellings when matching, so the switch orphans nothing) and a `disposition` written onto earlier rounds' still-open rows when a later round runs: `carried` (re-raised), `dismissed` (absent and named in `--decided`, reason kept), `suppressed` (absent, but the later round ran at a lower harshness that does not raise that severity — silence, not a fix), `fixed` (absent otherwise). A round whose JSON was salvaged disposes nothing; the next complete round settles everything still open. Two rounds on an identical `diff_sha` dispose nothing but `carried` (a re-run is not a fix). PR rows record the PR's head `branch`, so `lgtm rounds <pr>` shows the branch's `--local` rounds ahead of the PR's own; the two keys stay separately numbered. The write-side repo identity is the GitHub slug when one resolves (`--repo`, else the checkout's remote), else the checkout path; `rounds` reads both. `lgtm rounds <pr>|--local` and agent-mode `loop` (`round`, `previous`, `lastBugRound`, `roundsSinceBug`, `advice`, `budget`, `findingIds`) read it back. The loop's memory is applied by the tool, not the caller: the last stated `scope` is inherited (and required on an agent-mode loop's first round); findings settled with `lgtm dismiss <id> --reason` are injected into every later round's do-not-re-raise list; a round past `ROUND_BUDGET` (8) is refused before any model call unless `--override <reason>` is given, and the reason is stored; the stopping rule — `CLEAN_ROUNDS_TO_STOP` = 2 consecutive rounds without BUG/SECURITY, **or one judging round that raised nothing at all** (nothing left to fix means nothing a further round could verify) — counting only rounds that could judge, not a salvaged round or a re-run on an unchanged diff, is printed every round. A PR loop inherits its head branch's `--local` scope and dismissals, and the budget and clean-round count span both, so **the loop is the branch**, not the key — and a PR round disposes the branch's local findings as its own predecessors, so a BUG raised in the last local round is settled (or carried) by the PR's first round rather than left open forever. **A loop's lifetime is a run of rounds with no `LOOP_GAP_DAYS` (7) gap**: PR numbers are never reused but branch names are and PRs reopen, so scope, budget and the stopping rule consider only the current run; dismissals never age out (they are decisions about the code). The memory lives in the single-machine store deliberately — the loop runs on the machine that runs the reviewer, and the one thing that must travel with the repo (a dismissal's *reason*, if it is policy) belongs in `STANDARDS.md`, not here. **`--scope` is the one input agent mode refuses without** — an exception to the `--decided` "warn, never kill" rule, because the refusal is free (before any model call), instant, and its message is the fix; the `dwlf-ship` skill was changed in lockstep.
- Model-call environment (src/ai.ts): `LGTM_MODEL` and `LGTM_EFFORT` pin what reviews run on (default: the operator's `~/.claude/settings.json` `model` / `effortLevel` / `modelSettings`); `LGTM_CLAUDE_SETTING_SOURCES` (default empty) is the escape hatch for a setup whose settings carry auth or env routing.

**Depends on**
- GitHub CLI `gh`, authenticated, for PR fetch and comment posting *(inferred from: README prerequisites; src/github.ts)*.
- An AI CLI on PATH — `claude` (preferred) or `codex`, auto-detected; Action mode supplies `ANTHROPIC_API_KEY` instead *(inferred from: README prerequisites and workflow snippet)*. **Version floor for `claude`: 2.1.x** — the stripped-session flags (`--output-format json`, `--strict-mcp-config`, `--setting-sources`, `--effort`) are passed unconditionally, `--no-session-persistence` on one-off calls (arch, standards, quiz, recheck) and `--session-id` / `--resume` on review rounds (one persisted session per review LOOP, see the 2026-09-09 session decision), and `--json-schema` on a retry (verified against 2.1.267). lgtm also reads, but does not own, `~/.claude/settings.json` (`model`, `effortLevel`, `modelSettings`, and the routing keys it warns about); a renamed key there degrades to the CLI default with a stderr line, never a failure *(src/ai.ts; DWLF-205)*.
- `git` for repo resolution and `--local` base-ref diffs *(inferred from: src/git.ts; PR titles #20, #25)*.
- `git ls-files` for the architecture review's repository map (a two-level directory census plus the package's entry points and workflow names, capped by `--max-map-bytes`, default 8k) — the countable source behind a `codebase-pattern` or placement claim. No map when the target is another repository, or when the directory is not a checkout; either way the review records it in `skipped_checks`, and a TRUNCATED map is recorded as such so absence is never read as evidence *(src/repoMap.ts; DWLF-212)*.
- `rg` (preferred) or `grep` for the readers-of-what-this-writes search; neither present ⇒ the review says out loud that it is blind to consumers rather than reporting none *(src/readers.ts; DWLF-211)*.
- **Reads outside the repo, by explicit consent only:** `--add-dir <path>` / `LGTM_SIBLING_DIRS` name sibling checkouts to search for readers of what a diff writes. Nothing else in lgtm reads another repository, and a foreign reader is labelled in the prompt as one this diff cannot have updated *(src/readers.ts; DWLF-211)*.
- Optionally, a Stryker mutation report (`mutation.json`) in the target repo — **consumed, never produced**: generating it is the repo's job (CI or a local Stryker run). Missing report ⇒ a loud, actionable error on the explicit `quality` commands, and a no-op warning wherever quality later participates in a review (the brain.ts posture) *(src/quality.ts; Phase 0 decision, 24-Aug-2026)*.
- Optionally, a TICKET TRACKER via env — `LGTM_TICKETS_CMD` (any tracker, given the ref) is tried first, else an HTTP board at `LGTM_TICKETS_API` with `LGTM_TICKETS_TOKEN` (`DWLF_TICKETS_*` read as a fallback). **This is an outbound network call on any review whose title or branch carries a `LGTM_TICKET_PREFIX`-`<n>` ref**, bounded at 2.5s and skipped on any failure; the text it returns is untrusted and fenced *(src/ticket.ts; DWLF-210)*.
- Optionally, a second brain via env — `LGTM_BRAIN_CMD` → `LGTM_BRAIN_URL` → `LGTM_BRAIN_DIR`, tried in that order, first provider that yields anything wins *(inferred from: src/brain.ts header comment)*.
- npm runtime deps: `commander`, `prompts`, `chalk`, `better-sqlite3`, `jsonrepair` *(inferred from: package.json dependencies)*.

## Invariants
- Brain context can never break a review: no `LGTM_BRAIN_*` env → no-op; any provider failure, timeout, or bad output resolves to `''`; latency is bounded (`TIMEOUT_MS = 2500`, `MAX_ATTEMPTS = 14`). No code path may throw out of `fetchBrainContext` *(inferred from: src/brain.ts header comment and constants)*.
- Non-TTY stdin never hangs: interactive commands guard on `process.stdin.isTTY` and degrade to read-only or fail fast; `--agent`/`--auto`/`--batch` never prompt *(inferred from: PR #24 title)*.
- `--local` reviews never post anything to GitHub *(inferred from: PR #20; handbook "--local … NEVER posts")*.
- Malformed or truncated model JSON is recovered rather than failing the whole review; agent-mode output carries a `recovered` flag when salvage happened *(inferred from: PR titles #22, #23; `jsonrepair` dependency)*.
- Interactive mode posts nothing without per-finding operator approval *(inferred from: README "you decide which comments actually get posted")*.
- The reviewer runs one-shot with no repo access, so it must not assert unverifiable project conventions; convention-dependent findings stay conditional and are capped at SUGGESTION *(inferred from: PR #21 "convention-evidence prompt rule")*.
- Auxiliary inputs are best-effort: a bad or missing `--decided` file warns on stderr and never kills the review *(inferred from: PR #21; handbook)*.

## Standing decisions
- 2026-06-24 — Brain context is optional, pluggable (CMD → URL → DIR), and fully defensive — because reviews must work with zero configuration and a personal knowledge base must never block or break a review *(PR #18; rationale written in the src/brain.ts header)*.
- 2026-07-14 — Added `--decided` (dismissed-findings memory) and `--scope` (intent statement) — because multi-round fix→re-review loops churned on re-raised nitpicks and out-of-scope style flags *(PR #21; handbook rationale)*.
- 2026-07-14 — Added `--local` working-tree review against a base ref — so changes can be reviewed before a PR exists, without ever posting *(PR #20)*.
- 2026-07-23 — Interactive commands are TTY-guarded; non-TTY runs degrade read-only (`review`/`recheck`), keep cache and exit 1 (`retry`), or fail fast before spending an AI call (`quiz`) — because unconditional `prompts()` hung forever on piped/CI stdin *(PR #24)*.
- date unknown — Global install is a real `npm install -g .` (`install-global`), not `npm link` — because nvm Node-version switches break link-based globals *(README installation notes)*.
- 2026-08-12 — The mechanical quarter of the catalog is emitted as ESLint rules rather than left to the reviewer — because lint is free, instant, deterministic and non-negotiable, and every rule it enforces is a finding slot the capped AI pass no longer spends. Both artefacts derive from the same interview answers so they cannot drift *(src/standardsLint.ts)*.
- 2026-08-12 — Retroactive review GATES on structural lint findings rather than merely reporting them — because a function about to be split makes any judgement about its internals stale on arrival. Non-structural findings are suppressed instead of gated, since they invalidate nothing *(src/standardsReview.ts)*.
- 2026-08-11 — `standards init` is deliberately AI-free and deterministic (fixed contested-toggle questions against a heuristic repo scan; same answers ⇒ same document) — because the catalog IS the distillation, reproducibility makes the generated doc auditable, and the interview needs no model to select from a finite set. The review side still spends model tokens; the selection does not *(src/standardsInterview.ts header)*.

- 2026-08-24 — `quality` CONSUMES `mutation.json` rather than executing the target repo's test suite — because reading a report artifact is a far smaller invariant surface than running foreign builds (precedent: standardsReview shells to ESLint, seconds and no build; Stryker is minutes and a full toolchain). The per-file baseline is a COMMITTED repo file, not the sqlite store — the ratchet must travel with the repo (visible in PRs, diffable, CI-readable), and the store is single-machine and already listed as accepted debt. Baseline resets are LOUD, never inherited: a file absent from the baseline seeds at its current score and is reported (rename = one DROPPED + one NEW line), and a rewrite that LOWERS a committed score refuses without `--force` (then lists every fall) — you can shed history or lower the ratchet, never silently. `hotspots` is deliberately a REPORT (uncapped): only the later AI-triage phase emits capped findings, tagged `(mutant <mutator>)` mirroring `(standard <id>)` *(src/quality.ts; Phase-0 interview with Andy, 24-Aug-2026)*.
- 2026-09-09 — Every `claude --print` call is a STRIPPED session — `--strict-mcp-config --setting-sources '' --no-session-persistence --output-format json`, with the model and effort passed explicitly — because the bare invocation booted the operator's whole chat environment into each review: every MCP server's tool schemas, three layers of CLAUDE.md (including chat-style instructions a reviewer must not follow), and a saved transcript per call that had made the target repo's session directory 99% lgtm prompts. Measured on the same model: ~27k → ~17k prompt tokens before the first diff line. Stripping settings would silently change the model and effort, so those are resolved from the operator's settings and pinned rather than inherited; settings keys that route or authenticate (`apiKeyHelper`, `env`) are warned about, not silently dropped. The envelope's usage is what the review log now records — the diff-length estimate stays in its own column because 820 historical rows are in that unit and the two differ by ~3× *(src/ai.ts, src/db.ts; DWLF-205)*.
- 2026-09-09 — The review log records FINDINGS and their fate, not just runs — because 820 logged reviews could not answer "did the loop buy correctness?": `false_negative` was 0 everywhere and the only record of what a round found was the agent's transcript. Dispositions are inferred by the tool from round-to-round presence (plus the `--decided` file for dismissals) rather than asked of the operator, so they cost nothing to keep; the fingerprint is deliberately line-free (fixes move lines) and tag-free (a finding re-tagged `(out of scope)` is the same finding), and it is stored as a derived column of stored `file` + `title` — the model-supplied fingerprint of prompt v2 superseded it WITHOUT a migration: the raw fingerprint is stored alongside, and a round offers both spellings of every finding when matching, so no open row is orphaned and nothing has to be recomputed. The rules for WHETHER a round may judge earlier ones (round 1, salvaged output, unchanged diff) live in `disposePreviousRound` beside the rules for WHICH disposition applies, so no caller carries them. `--local` rounds are logged with `pr_number = 0` under a branch key, ending the blind spot in the mode the ship loop runs first *(src/db.ts, src/cli.ts; DWLF-151)*.
- 2026-09-09 — The anti-churn controls are STRUCTURE in the tool, not instructions to its caller — scope inheritance, automatic injection of recorded dismissals, a refused round past the budget, and the stopping rule printed from the log — because the 2-Sep round budget written into the `dwlf-ship` skill was measurably ignored (PRs after it averaged 6.8 rounds vs 2.9 before; `--decided` unused since) and a rule the agent has to remember mid-loop is a rule that is not there. The budget refuses BEFORE the model call so a refused round costs nothing; the override is a recorded reason, not a bypass, so the log can show which loops needed one and why *(src/cli.ts pre-flight, src/db.ts loopContext/dismissFindings/stopAdvice; DWLF-153)*.
- 2026-09-09 — The model is chosen PER ROUND by the tool (`pickRoundModel`), not inherited from the session: the full model for every first look and every non-chill round; the cheaper `LGTM_LATE_MODEL` (default the current Sonnet, `claude-sonnet-5`) only on a chill round ≥ 4 whose diff moved by ≤ 50 lines and with no BUG/SECURITY finding from an earlier round still open (a fix is verified on the full model) — because a late "is it safe now?" round on a settled delta is the cheapest question lgtm asks and was running on the most expensive model available, while a first look or a fix-verification is exactly where the full model earns its price. `--model` overrides; `LGTM_LATE_MODEL=off` disables; the default late model is assumed only when the full model is a first-party `claude-…` id (a Bedrock/Vertex operator opts in by naming one); the chosen model AND the reason are on the row (`model_id`, `model_reason`) so the saving is measured, never asserted. The same policy lowers harshness to chill on a late round with no BUG/SECURITY open when `-H` was not given — the tool owns the trigger, not the caller. The "diff moved" gate is a SIZE proxy (added+removed line count vs the previous round): a same-size rewrite reads as delta 0; chosen because the rounds' diffs are not stored, and accepted until a real churn measure is worth its storage. An unparsable reply (the cheaper model's first live round answered in prose) is retried on the same model with `REVIEW_SCHEMA` enforced via `--json-schema`, then — if the policy had picked the cheaper model — once more on the full model; the schema is a retry tool, not a default, because measured it adds a second CLI turn that misses the prompt cache (2.3× the cost of a small call). Every attempt that yields no review is logged as `failed` (its spend is real; it judges nothing) *(src/ai.ts, src/review.ts, src/cli.ts; DWLF-206)*.
- 2026-09-09 — A review loop runs inside ONE persisted Claude session, resumed every round (`--session-id` / `--resume`, `LGTM_SESSIONS=off` or `--fresh` to opt out) — because the prompt cache is the largest lever the loop has and `claude --print` looks the cache up at exactly two points, after its own system prompt and at the end of the conversation, so no prompt ORDERING can make a fresh call reuse the last one (measured: an appended system prompt was re-created every call; a resumed turn read 86k of 86k from cache and cost a twentieth). A resumed round sends only the files whose sha1 changed since the session last saw them, plus the current diff and the per-round instructions; it keeps the session's model when the model ROLES fit — the same role, or a full-model session carrying a round that would merely have gone cheaper (a cached full-model turn beats an uncached cheaper one); a cheaper-model session is not continued into a round the policy says needs the full model, and an explicit `--model` is matched exactly. Roles (`full` / `late:<id>` / `explicit:<id>`) are compared rather than CLI-reported ids, because settings may name the default as an alias. The cost is one transcript per LOOP under the CLI's project dir (the DWLF-205 objection was one per CALL), whose lifetime is the CLI's own retention (`cleanupPeriodDays`, 30 by default) — lgtm records the id and takes no other responsibility for the file; a session that cannot be continued gets one fresh full round before any other recovery, and a failure that spent nothing (the CLI could not find the session) is not logged as a round. A session is not continued past `SESSION_CONTEXT_BUDGET` (700k tokens of held context plus what the round would add): the CLI compacts a conversation nearing the 1M window — measured, an 883k-token session plus a 150k message came back as 228k with the whole cache lost — and a compacted session reviews from a summary; a fresh full prompt is cheaper and better. The full-model role NAMES the model (`full:<id>`), so changing the operator's default restarts the session — the prompt cache is model-scoped. With no model configured anywhere lgtm reads, the role is `full:cli-default` and a change of the CLI's own default is undetectable; `LGTM_MODEL` is the fix and the stderr line says so. Continuation compares everything the reviewer was told, not just files: the system prompt, charter, standards and handbook blocks are fingerprinted under pseudo-paths, an edited charter is re-sent as updated context, and a changed system prompt (lgtm upgraded mid-loop) restarts the session. The resumed round's tail is BUILT, never sliced out of the full prompt by a marker — a reviewed file can contain any heading (this repo's own `review.ts` does), and the first version of this feature re-sent half the prompt every round for exactly that reason. The stable-first prompt order stands as the prerequisite that keeps the first turn — and any fresh restart — cacheable *(src/ai.ts, src/review.ts, src/cli.ts; DWLF-215)*.
- 2026-09-10 — Reviews carry a READERS section: who consumes the identifiers a diff writes, found by grep rather than by a model — because "who else READS what this WRITES?" is the question a diff review structurally cannot answer (the reader is never in the diff), and it is the class that cost DWLF-127 28 rounds. Deterministic and one hop deep: identifiers out of the added production lines, the fields of any payload helper they spread into their output, then a search of this repo and any sibling named by `--add-dir` / `LGTM_SIBLING_DIRS`, budgeted per repository so a foreign reader is never crowded out by local hits. Measured against the case that motivated it (indicators e4ea81e, whose consumer keyed rows on `payload.pivotTime` in another repo): the expander surfaced the consumer and produced a cross-repo finding no previous arm produced, but did NOT name the sort-key defect — the mechanism that catches that one remains a charter contract phrased as a CHECK. Adopted on the capability, not on that case *(src/readers.ts; DWLF-211, experiment on DWLF-207)*.
- 2026-09-10 — A model call has a TIMEOUT (`DEFAULT_TIMEOUT_MS` 15 min, `LGTM_TIMEOUT_MS` to change) and a call that hits it raises an error naming the prompt size and the lever — because the failure that started this ticket was silence: four attempts on a large PR returned nothing at all, not even "too large", which reads as a broken tool rather than a slow one. Two rules come with it: a timeout is **never retried** (each recovery rung would spend the same budget again, turning one wait into three) and it **is** logged as a round, because the time and tokens were spent whatever came back. Paired with loop sessions (DWLF-215), which stop later rounds re-sending the whole change, the underlying cause is also gone: a first round pays for the full context, every later round pays for its delta *(src/ai.ts, src/recovery.ts; DWLF-137)*.
- 2026-09-10 — The architecture review is given a REPOSITORY MAP — a two-level directory census, the package's entry points and workflow names — because `lgtm arch` is asked to judge placement and to make COUNTED `codebase-pattern` claims while being shown only the files the diff touches, so every such claim outside the diff was a guess the prompt itself forbids. Deliberately the ARCH altitude only: `lgtm review` keeps its anti-fabrication rule and gets its repo grounding from related files and the readers search instead. The map is the LOCAL checkout and says so, naming its revision and whether it is dirty — a count from it is a claim about this working copy, not about the reviewed ref. It is skipped entirely when `--repo` names a repository this checkout is not, since mapping the cwd there would describe the wrong codebase, and `skipped_checks` distinguishes absent from TRUNCATED so a missing directory is never read as evidence *(src/repoMap.ts; DWLF-212)*.
- 2026-09-10 — Every externally-written span in a prompt is FENCED, warned about and made unclosable, and the verifier's use of one is checked in code — because ticket text (DWLF-210) is the first such span but not the only one: a pull request DESCRIPTION is written by whoever opened the PR, a fork in the Action posture, and was interpolated raw into the same prompt in a run that posts comments unattended. One helper (`fenced`) does both. For the verifier specifically — the model whose answers DELETE findings — prose is not the guard: a `refuted` verdict must quote text that actually appears in the CODE it was shown, and the haystack deliberately excludes the ticket and the findings list, since a check whose haystack contained attacker-writable text would accept a refutation quoting the attacker's own planted lines. `refuted` is the only verdict that drops a BUG outright, and `wasShown` cannot catch an invented quote about a file that WAS sent *(src/ticket.ts, src/review.ts, src/verify.ts; DWLF-210, arch review)*.
- 2026-09-10 — Findings are PROVED OR DROPPED by a second model call before the agent sees them (`--verify`, on by default in `--agent` mode) — because roughly nine in ten round-1 findings on a long loop were not defects (DWLF-127: 109 → 12) and each one cost the driving agent a read-verify-dismiss cycle before the next real fix, and because reviewer and author are the same model family, so a second family (`--verify-ai codex`) is the only cheap way to decorrelate their blind spots. Three rules make it a filter rather than a second reviewer: it may NEVER add a finding (a second generator is a second source of churn — verdicts are matched to the ids it was given and anything else is discarded); it may lower a severity and never raise one, with the DROP decision taken on the severity the REVIEWER gave, so "downgrade to an opinion, then drop it as unproven" is not a route by which a BUG can disappear; and absence of proof is not refutation — a refutation with nothing quoted is recorded as `unproven`, and an `unproven` BUG/SECURITY is KEPT at low confidence while only an unproven OPINION is dropped, because a false drop of a real finding is the one failure this pass must not have. `unproven` is deliberately narrow — the relevant code WAS shown and still does not establish the claim — and is separated from `unshown`, which drops nothing: measured on this feature's own third round, before that split existed, all three of the pass's live drops were TRUE findings whose proof sat in a file it had never been given. Both halves of that fix ship together: the verdict for it, and the whole of any other file a finding NAMES becoming part of what it is shown, with the list of files it holds stated in the prompt — a verdict about one's own context is only honest if one is told what that context is. A finding it says nothing about is `unverified`, deliberately a different value from `unproven`: silence must never be what deletes a finding. The safety property is enforced by the CALLER, not by the prompt: `buildWindows` knows exactly which files it put in front of the verifier, so a verdict about a finding whose own file — or any file the finding's text names — was never sent is rewritten to `unshown` whatever the model called it. Leaving that in prose alone would make it model-dependent, and weakest in precisely the configurations this feature recommends for decorrelation (a smaller model, or another family). Drops are stored on their OWN column (`findings.dropped`), not by widening `disposition`: that column keeps its single meaning, "what a later ROUND decided", so a query for open findings does not silently inherit the verifier's opinion, a dropped row is not settled at birth, and "dropped in round N, re-raised and confirmed in round N+1" stays a join anyone can write. Drops are excluded from `bySeverity`, `lastBugRound`, `cleanRounds` and `openBugs` — refuting a false BUG has to actually buy the loop something — and are NOT fed back as dismissals, so one bad drop cannot silence a real bug for the rest of a loop. Each round records `verify_rules`, the version of the verdict vocabulary and drop rule that produced its verdicts, so a stored verdict can be attributed to the rules behind it rather than summed with verdicts that meant something else — the same "store alongside, never rewrite" precedent as DWLF-151's fingerprint change. The verifier is given the diff and a WINDOW around each finding rather than the review's whole context, so its cost scales with the number of findings and not with the repository; the charter and STANDARDS.md travel only with a finding that cites them, since they are the only evidence such a finding can have. A verifier that fails, times out or answers with nonsense leaves every finding exactly as raised and says so on the row (`verify_ran` / `verify_failed`) — "nothing was dropped", "nothing was checked" and "no pass ran" are three different rounds, and only the first belongs in a drop rate's denominator. `model_id` keeps naming the model that REVIEWED (the verifier's is in `verify_model`), so DWLF-206's per-model saving is still measurable off that column; the review's own cost is `cost_usd - COALESCE(verify_cost_usd, 0)` in both the measured and the codex case, since an unmeasured verifier contributes nothing to either. The pass's spend is added to the round's cost but NOT to `sent_tokens` / `context_tokens`: those are read back by `planSession` to decide whether the loop's session has room, and the verifier's prompt is not in that session, so summing it would abandon the session rounds early and re-send the whole prompt uncached — the cost DWLF-215 exists to avoid. `--show-dropped` changes what is DISPLAYED and never what is posted, since a refuted finding on a PR carries no marker saying it was refuted *(src/verify.ts, src/db.ts; DWLF-209)*.
- 2026-09-10 — Reviews are given THE TICKET the change was asked to deliver, and raise at most one question-shaped `(ticket)` SUGGESTION naming acceptance criteria the diff does not visibly address — because nothing in the toolchain checked a change against what was asked for: `review` checks the code, `arch` checks the system, and "did it do the ticket?" was left to the same agent that wrote it, which is the pattern behind work being re-dated rather than finished. The finding is capped at one, never a BUG, never a gate, and phrased as a QUESTION on purpose: a criterion may be met by another PR, by work already merged, or outside the diff, so an assertion would be wrong more often than it was right. Ticket text is treated as UNTRUSTED INPUT, the first such span lgtm puts in a prompt: it is fenced in explicit BEGIN/END data markers, labelled as data written by anyone with board access, and lgtm's own instruction is stated AFTER it so the last thing the reviewer reads is not the ticket's — an instruction found inside is something to report, never to obey. The integration follows `brain.ts` including its escape hatch, not only its failure semantics: `LGTM_TICKETS_CMD` reaches ANY tracker (the ref arrives as `$LGTM_TICKET_REF` and as an argument) and is tried before the board API, and `LGTM_TICKET_PREFIX` sets the ref shape — because lgtm is a general tool DWLF happens to consume, and hard-coding one organisation's prefix would put that literal in the regex, the flags, the prompt and the docs while leaving every other tracker unreachable. Off unless a provider is configured, a 2.5s timeout, and no ref / no config / unreachable / 404 / junk all resolving to no block, because a review must never be blocked or delayed by a ticket tracker. The block sits in the STABLE half of the prompt beside the charter and standards (a ticket does not move while the change does) and is fingerprinted as `@ticket`, so an edited ticket reaches a resumed session as updated context. `lgtm arch` gets the same block — it is precisely the `rationale_found` input its schema asks for — and records an unreadable ticket in `skipped_checks` (distinguishing "no board access", an opt-out, from a configured board that failed, and taking that distinction from a typed value rather than by regex on a human-readable message); a change with NO ticket ref says nothing at all, since a permanent skip line in every repo that does not use the board would be noise. The check is recorded on the round (`ticket_ref`, `ticket_present`) so "it never fired because the diff covered the ticket", "the board 404'd every round" and "no board was configured" are different rows — the question this feature is justified by needs a query behind it, not a recollection. Two consequences of ticket text reaching a model were bought with its own review rounds: the fence is made unclosable by neutralising any dash-run line in the DATA (the block's shape is published in the README, so a body containing the END marker would otherwise close it early and render where lgtm's own instructions belong) — deterministically, not with a per-run nonce, because the block is fingerprinted as `@ticket` and a nonce would re-send it every round; and the warning travels with the DATA rather than with the reviewer's instructions, because the span now reaches the verifier too, which is a model whose answers DELETE findings. The verifier gets the data half only: the reviewer is told to add exactly one finding and the verifier's own first rule is that it may not add any. Finally, a finding tagged `(ticket)`, `(charter)` or `(standard …)` is NEVER dropped merely as `unproven` (it can still be refuted): the completeness check asserts an ABSENCE, which has no lines to quote, so without the exemption DWLF-209's opinion-drop could silently delete a whole capped feature shipped one commit earlier. Which document a finding cites is a DECLARED field (`cites`, a closed enum — enforced by `citedDocument`'s lookup rather than by the schema, which is only sent on a recovery retry, and never by a bare object index: a raw model string reaching one would resolve `constructor` to an inherited value) rather than a prefix parsed back out of the rendered title. When the field and the prefix disagree the TITLE wins, because it is what every human surface shows and the filter must not act on a different document from the one the reader is told about. Whether the cited document was actually SENT is the caller's decision, not a prompt sentence: it resolves the charter, STANDARDS.md and the ticket, says which of them it put in the prompt, and a verdict about one it did not send is rewritten to `unshown` exactly as a verdict about an unsent file is — but only for a finding still WITHIN its document's cap, since otherwise "the document was not resolvable" would be an uncapped route to undroppable findings in most repos (few resolve a ticket board, many have no STANDARDS.md), and it is the case where the tag is least trustworthy, the reviewer never having been given the block that asks for those findings — control flow should not turn on how a model phrased a heading, and `title` already carries display text and the pre-fingerprint matching fallback; the prefix remains the fallback so codex, which gets no schema, and rows written before the field still work. The exemption is itself CAPPED in code — one charter, one ticket, three standards findings per round, `DOC_TAG_EXEMPT` — because the caps those checks state are instructions to a model and the exemption is keyed on a title prefix the reviewer chooses: unbounded, it is a switch that turns the filter off with no signal that it happened *(src/ticket.ts, src/verify.ts; DWLF-210)*.
- 2026-09-10 — `standards init` LINTS THE FILE IT JUST WROTE with the target repo's own ESLint, and says plainly when that repo's lint will now fail — because it happened: the fragment is a `.js` file, dwlf-indicators lints with `recommendedTypeChecked`, the file belongs to no tsconfig project, every typed rule threw, and `eslint .` exited 2 and took the pre-commit hook with it. A generator that writes a file into someone else's repo owns whether that file passes their build, and finding out costs one bounded subprocess. The probe lints the fragment's DIRECTORY, never the file: naming a file explicitly makes ESLint lint it even when the config ignores it, so a file-shaped probe would report broken forever in a repo that had already applied the remedy — the false positive was observed in live verification before it shipped. Exit 2 (the config cannot lint it at all) is reported separately from exit 1 (it lints and complains), since only the first takes the whole lint down. The remedy is PRINTED, never applied: editing a config lgtm did not generate, non-interactively, on the strength of a heuristic, is the operator's call *(src/standardsInterview.ts; DWLF-221)*.
