# lgtm — architecture charter

## Purpose & scope boundary
lgtm is a single-operator, human-in-the-loop AI PR-review CLI: it fetches a GitHub PR (or diffs the local working tree), has an LLM CLI produce findings, and keeps the human in charge of what actually gets posted *(inferred from: package.json description "AI-powered PR review CLI — you stay in control"; README)*. A second, unattended posture exists for agents and CI: `--agent`/`--auto` emit findings as JSON, `--batch` posts all comments without prompting, and a GitHub Actions recipe runs it on every PR push *(inferred from: PR titles #9, #11, #24; README "GitHub Actions Mode")*.

**Not for:**
- A hosted service or GitHub App. Only a CLI binary ships (`bin: {"lgtm": "dist/cli.js"}`); the App exists solely as design docs *(inferred from: package.json `bin`; docs/ARCHITECTURE-GITHUB-APP.md and docs/IMPLEMENTATION-TICKETS.md with no server code under src/)*.
- Knowledge-base content. Engineering handbooks live in an external "second brain"; this repo only *fetches* that context through pluggable providers and must keep working without one *(inferred from: src/brain.ts header comment)*.
- DWLF production code. lgtm is standalone local tooling consumed *by* the DWLF workflow, not part of its deploy cascade or code-freeze *(inferred from: engineering handbook "Conventions & deploy")*.

## Interfaces & dependencies
**Exposes**
- The `lgtm` global CLI (`dist/cli.js`), commands: `review [pr]` (incl. `--local` working-tree mode), `arch` (`review [pr]`/`new`/`init` — architecture altitude: decision records against an ARCHITECTURE.md charter, one summary comment, never inline), `standards` (`init` — AI-free, scan-informed generation of STANDARDS.md from the built-in clean-code catalog), `recheck`, `retry`, `tag`, `report`, `quiz` *(inferred from: package.json `bin`; command registrations in src/cli.ts; PR #26)*. Consumers: the operator interactively; coding agents and CI via `--agent`/`--auto` (JSON findings) and `--batch` (post-all, no prompts) *(inferred from: PR titles #8, #11; the DWLF workflow's `lgtm review <PR#> --agent` in CLAUDE.md)*.
- Charter/system input contract: `ARCHITECTURE.md` (root, then `docs/`, then `.lgtm/`) with `title:`/`system:` frontmatter as the only code-parsed fields; `SYSTEM.md` via the `system:` pointer or `LGTM_SYSTEM_DIR` *(inferred from: src/charter.ts; PR #26)*.
- Standards input contract: `STANDARDS.md` (root, then `docs/`, then `.lgtm/`) — the repo's normative selection from the clean-code catalog (`src/standardsCatalog.ts`; rationale in `docs/clean-code-catalog.md`). Consumed by `review` for up to three `(standard <id>)` SUGGESTION findings; only the filename search order is code-parsed; `--no-standards` opts out per run *(src/standards.ts)*.
- Standards OUTPUT contract: `.lgtm/standards.eslint.js` — the mechanical subset of the same selections, emitted by `standards init` as a `standardsRules` fragment (CommonJS or ESM per the target's `package.json type`) for the repo to spread into its own ESLint config. Generated, never hand-edited; regenerating is the supported way to change it *(src/standardsLint.ts)*.
- `standards review <file|dir>` — the retroactive altitude: renders an existing file as a synthetic whole-file diff, runs ESLint first, and gates the AI pass on outstanding **structural** findings (length/complexity/nesting/params), passing non-structural ones through the `--decided` channel so no capped finding slot is spent on what lint already reported *(src/standardsReview.ts)*.
- `quality` (`baseline`/`hotspots`) — the 4th altitude, Phase 1 (24-Aug-2026): *do the tests actually hold the code down?* Deterministic, no AI call. `baseline` reads a Stryker `mutation.json` (searched at `reports/mutation/mutation.json` → `.lgtm/mutation.json` → `mutation.json`, or `--report`) and writes per-file scores to the target repo's **committed** `.lgtm/mutation-baseline.json`; `hotspots` ranks the burn-down worklist by `(1−score) × mutants × (1+churn)` — a v1 formula, validated by reproducing the dwlf-indicators baseline's known worst files (orderBlocks 3.7%, regime 22.9% flagged on its open bug); full-history churn is a deliberate risk input and a known bias to revisit if a real repo's list orders by age rather than weakness — and cross-checks open issues per file via `gh` (**fix-before-harden**: hardening a file with an open correctness bug cements the bug), degrading to an explicit "unchecked"/"partial" when `gh` fails or truncates. The ranking is deterministic from report+git; the issue column deliberately reads LIVE tracker state *(src/quality.ts)*.
- Local data: a review log in SQLite at `~/.lgtm/reviews.db` (`LGTM_DB_PATH` overrides; src/db.ts) and metrics/false-negative data in cwd-relative `data/reviews.json` (src/metrics/reviewLogger.js). Each logged review carries two token figures in two units and they are never mixed: `token_count` (the historical diff+context length estimate) and the measured columns `prompt_tokens` / `cache_read_tokens` / `cache_creation_tokens` / `output_tokens` / `cost_usd` / `duration_ms` / `model_id`, present only when `usage_source = 'measured'` (every model call in the run returned an envelope). Agent-mode output exposes the same as `context.usage`. Every review — PR **and** `--local` — is also a **round** under a `round_key` (`pr:<n>` or `local:<branch>`), with one `findings` row per finding (severity, file, line, fingerprint = file + normalised title) and a `disposition` written onto earlier rounds' still-open rows when a later round runs: `carried` (re-raised), `dismissed` (absent and named in `--decided`, reason kept), `suppressed` (absent, but the later round ran at a lower harshness that does not raise that severity — silence, not a fix), `fixed` (absent otherwise). A round whose JSON was salvaged disposes nothing; the next complete round settles everything still open. Two rounds on an identical `diff_sha` dispose nothing but `carried` (a re-run is not a fix). PR rows record the PR's head `branch`, so `lgtm rounds <pr>` shows the branch's `--local` rounds ahead of the PR's own; the two keys stay separately numbered. The write-side repo identity is the GitHub slug when one resolves (`--repo`, else the checkout's remote), else the checkout path; `rounds` reads both. `lgtm rounds <pr>|--local` and agent-mode `loop` (`round`, `previous`, `lastBugRound`, `roundsSinceBug`) read it back — the stopping rule's evidence.
- Model-call environment (src/ai.ts): `LGTM_MODEL` and `LGTM_EFFORT` pin what reviews run on (default: the operator's `~/.claude/settings.json` `model` / `effortLevel` / `modelSettings`); `LGTM_CLAUDE_SETTING_SOURCES` (default empty) is the escape hatch for a setup whose settings carry auth or env routing.

**Depends on**
- GitHub CLI `gh`, authenticated, for PR fetch and comment posting *(inferred from: README prerequisites; src/github.ts)*.
- An AI CLI on PATH — `claude` (preferred) or `codex`, auto-detected; Action mode supplies `ANTHROPIC_API_KEY` instead *(inferred from: README prerequisites and workflow snippet)*. **Version floor for `claude`: 2.1.x** — the stripped-session flags (`--output-format json`, `--strict-mcp-config`, `--setting-sources`, `--no-session-persistence`, `--effort`) are passed unconditionally (verified against 2.1.266). lgtm also reads, but does not own, `~/.claude/settings.json` (`model`, `effortLevel`, `modelSettings`, and the routing keys it warns about); a renamed key there degrades to the CLI default with a stderr line, never a failure *(src/ai.ts; DWLF-205)*.
- `git` for repo resolution and `--local` base-ref diffs *(inferred from: src/git.ts; PR titles #20, #25)*.
- Optionally, a Stryker mutation report (`mutation.json`) in the target repo — **consumed, never produced**: generating it is the repo's job (CI or a local Stryker run). Missing report ⇒ a loud, actionable error on the explicit `quality` commands, and a no-op warning wherever quality later participates in a review (the brain.ts posture) *(src/quality.ts; Phase 0 decision, 24-Aug-2026)*.
- Optionally, a second brain via env — `LGTM_BRAIN_CMD` → `LGTM_BRAIN_URL` → `LGTM_BRAIN_DIR`, tried in that order, first provider that yields anything wins *(inferred from: src/brain.ts header comment)*.
- npm runtime deps: `commander`, `prompts`, `chalk`, `better-sqlite3`, `jsonrepair` *(inferred from: package.json dependencies)*.

## Invariants
- Brain context can never break a review: no `LGTM_BRAIN_*` env → no-op; any provider failure, timeout, or bad output resolves to `''`; latency is bounded (`TIMEOUT_MS = 2500`, `MAX_ATTEMPTS = 14`). No code path may throw out of `fetchBrainContext` *(inferred from: src/brain.ts header comment and constants)*.
- Non-TTY stdin never hangs: interactive commands guard on `process.stdin.isTTY` and degrade to read-only or fail fast; `--agent`/`--auto`/`--batch` never prompt *(inferred from: PR #24 title)*.
- `--local` reviews never post anything to GitHub *(inferred from: PR #20; handbook "--local … NEVER posts")*.
- Malformed or truncated model JSON is recovered rather than failing the whole review; agent-mode output carries a `recovered` flag when salvage happened *(inferred from: PR titles #22, #23; `jsonrepair` dependency)*.
- Interactive mode posts nothing without per-finding operator approval *(inferred from: README "you decide which comments actually get posted")*.
- The reviewer runs one-shot with no repo access, so it must not assert unverifiable project conventions; convention-dependent findings stay conditional and are capped at SUGGESTION *(inferred from: PR #21 "convention-evidence prompt rule")*.
- Auxiliary inputs are best-effort: a bad or missing `--decided` file warns on stderr and never kills the review *(inferred from: PR #21; handbook)*.

## Standing decisions
- 2026-06-24 — Brain context is optional, pluggable (CMD → URL → DIR), and fully defensive — because reviews must work with zero configuration and a personal knowledge base must never block or break a review *(PR #18; rationale written in the src/brain.ts header)*.
- 2026-07-14 — Added `--decided` (dismissed-findings memory) and `--scope` (intent statement) — because multi-round fix→re-review loops churned on re-raised nitpicks and out-of-scope style flags *(PR #21; handbook rationale)*.
- 2026-07-14 — Added `--local` working-tree review against a base ref — so changes can be reviewed before a PR exists, without ever posting *(PR #20)*.
- 2026-07-23 — Interactive commands are TTY-guarded; non-TTY runs degrade read-only (`review`/`recheck`), keep cache and exit 1 (`retry`), or fail fast before spending an AI call (`quiz`) — because unconditional `prompts()` hung forever on piped/CI stdin *(PR #24)*.
- date unknown — Global install is a real `npm install -g .` (`install-global`), not `npm link` — because nvm Node-version switches break link-based globals *(README installation notes)*.
- 2026-08-12 — The mechanical quarter of the catalog is emitted as ESLint rules rather than left to the reviewer — because lint is free, instant, deterministic and non-negotiable, and every rule it enforces is a finding slot the capped AI pass no longer spends. Both artefacts derive from the same interview answers so they cannot drift *(src/standardsLint.ts)*.
- 2026-08-12 — Retroactive review GATES on structural lint findings rather than merely reporting them — because a function about to be split makes any judgement about its internals stale on arrival. Non-structural findings are suppressed instead of gated, since they invalidate nothing *(src/standardsReview.ts)*.
- 2026-08-11 — `standards init` is deliberately AI-free and deterministic (fixed contested-toggle questions against a heuristic repo scan; same answers ⇒ same document) — because the catalog IS the distillation, reproducibility makes the generated doc auditable, and the interview needs no model to select from a finite set. The review side still spends model tokens; the selection does not *(src/standardsInterview.ts header)*.

- 2026-08-24 — `quality` CONSUMES `mutation.json` rather than executing the target repo's test suite — because reading a report artifact is a far smaller invariant surface than running foreign builds (precedent: standardsReview shells to ESLint, seconds and no build; Stryker is minutes and a full toolchain). The per-file baseline is a COMMITTED repo file, not the sqlite store — the ratchet must travel with the repo (visible in PRs, diffable, CI-readable), and the store is single-machine and already listed as accepted debt. Baseline resets are LOUD, never inherited: a file absent from the baseline seeds at its current score and is reported (rename = one DROPPED + one NEW line), and a rewrite that LOWERS a committed score refuses without `--force` (then lists every fall) — you can shed history or lower the ratchet, never silently. `hotspots` is deliberately a REPORT (uncapped): only the later AI-triage phase emits capped findings, tagged `(mutant <mutator>)` mirroring `(standard <id>)` *(src/quality.ts; Phase-0 interview with Andy, 24-Aug-2026)*.
- 2026-09-09 — Every `claude --print` call is a STRIPPED session — `--strict-mcp-config --setting-sources '' --no-session-persistence --output-format json`, with the model and effort passed explicitly — because the bare invocation booted the operator's whole chat environment into each review: every MCP server's tool schemas, three layers of CLAUDE.md (including chat-style instructions a reviewer must not follow), and a saved transcript per call that had made the target repo's session directory 99% lgtm prompts. Measured on the same model: ~27k → ~17k prompt tokens before the first diff line. Stripping settings would silently change the model and effort, so those are resolved from the operator's settings and pinned rather than inherited; settings keys that route or authenticate (`apiKeyHelper`, `env`) are warned about, not silently dropped. The envelope's usage is what the review log now records — the diff-length estimate stays in its own column because 820 historical rows are in that unit and the two differ by ~3× *(src/ai.ts, src/db.ts; DWLF-205)*.
- 2026-09-09 — The review log records FINDINGS and their fate, not just runs — because 820 logged reviews could not answer "did the loop buy correctness?": `false_negative` was 0 everywhere and the only record of what a round found was the agent's transcript. Dispositions are inferred by the tool from round-to-round presence (plus the `--decided` file for dismissals) rather than asked of the operator, so they cost nothing to keep; the fingerprint is deliberately line-free (fixes move lines) and tag-free (a finding re-tagged `(out of scope)` is the same finding), and it is stored as a derived column of stored `file` + `title` — a sharper algorithm (the model-supplied fingerprint of prompt v2) recomputes it for open rows in `migrate()` rather than letting them all read as fixed. The rules for WHETHER a round may judge earlier ones (round 1, salvaged output, unchanged diff) live in `disposePreviousRound` beside the rules for WHICH disposition applies, so no caller carries them. `--local` rounds are logged with `pr_number = 0` under a branch key, ending the blind spot in the mode the ship loop runs first *(src/db.ts, src/cli.ts; DWLF-151)*.
